Support

Last updated 28 October 2026

Questions, bug reports, and feature requests for mac4DSTEM and macTEM all go to one address. I read everything.

mail@mac4dstem.com

Both applications are developed by one person alongside other work, so replies are not instant — but every report is looked at. There is no support contract and no charge; the applications are free. Reports can also be opened as issues on GitHub: mac4DSTEM, macTEM.

Requirements

  • macOS 27 or later for mac4DSTEM 5 and macTEM 1. For macOS 14–26, mac4DSTEM 3.0.0 remains available.
  • Apple silicon — M-series Macs. Intel Macs are not supported.
  • No external runtime, toolchain, Python environment, or library installation. Every dependency ships inside the application bundle.
  • Enough free disk space for your datasets and any exported products. Memory needs scale with the size of the scan, detector, image or spectrum image.

What each application opens

  • mac4DSTEM: 4D-STEM datasets from py4DSTEM and other EMD/HDF5 files, Gatan DM3/DM4, Merlin MIB and EMPAD RAW, and EDX spectrum images on their own or with the 4D scan.
  • macTEM: images, stacks and spectrum images from DigitalMicrograph (.dm3, .dm4), Velox (.emd), TIFF and MRC.

Reporting a problem

A report is most useful when it lets me reproduce what you saw. Where you can, include:

  • Which application, what you did, what you expected, and what happened instead.
  • The application version and your macOS version and Mac model.
  • The file's format and shape (scan and detector shape for 4D-STEM, image size or channel count otherwise).
  • The room or step where it went wrong, as named in the sidebar.
  • A screenshot of the window, including any diagnostics shown alongside the result.

Please do not send datasets as email attachments. If reproducing an issue needs the data, say so and we can arrange a transfer.

Known limitations

  • In mac4DSTEM, the Merlin MIB and EMPAD RAW readers are preview-grade, pending further vendor data. If a file from either detector loads incorrectly, a report with the file's header is particularly valuable.
  • Where a measurement is not yet validated against a dataset with known truth, the result is labelled as such in the interface. Those labels are deliberate — treat them as part of the result.
  • Verification is numerical: every number is tested against the Python package it is ported from, within that package's own tolerance, rather than against the rendered output.

Results and interoperability

mac4DSTEM exports Bragg vectors, calibrated datacubes, and preprocessed products to EMD, readable directly in py4DSTEM. macTEM exports its measurements as CSV, spectra as MSA, and images as PNG with a scale bar. If you need a result in a format that is not currently offered, that is a reasonable thing to ask for.

Citing the methods

The numerics are ported from the Python packages the field already uses and validated against them; the kits page names each one. Work published using mac4DSTEM should cite py4DSTEM for the underlying methods; work using macTEM should cite the package behind the method used, for example HyperSpy and exSpy for spectroscopy.
